# Interface internationalization (FR / DE / EN)

## Current State
- The web interface is trilingual and switches live through the FR | DE | EN button group
  at the top right of the header.
- Initial language: the saved choice in localStorage key `agent-office.lang`, else the first
  supported entry of `navigator.languages`, else `fr`. `<html lang>` follows the language.
- The current language lives in the zustand store `packages/web/src/store.ts` (`lang`,
  `setLang`, which also updates `<html lang>` and saves the choice).

## Relevant Files
- `packages/web/src/i18n/fr.ts` — reference dictionary; defines `type Messages = typeof fr`.
- `packages/web/src/i18n/de.ts`, `en.ts` — typed `Messages`; a missing or extra key fails
  `npm run typecheck`.
- `packages/web/src/i18n/index.ts` — `APP_NAME_PARTS`, `APP_NAME`, `Lang`, `LANGS`, `MESSAGES`,
  `STORAGE_KEY`, `detectLang`, `initialLang`, `saveLang`.
- `packages/web/src/i18n/useT.ts` — `useT()` → `{ t, lang }`.
- `packages/web/src/i18n/plural.ts` — plurals via `Intl.PluralRules`.
- `packages/web/src/ui/LangSwitcher.tsx` — the switcher.
- `packages/web/src/ui/AppName.tsx` — the styled product-name brand (see Notes).
- `packages/web/src/format.ts` — non-React formatters taking `t: Messages`: `stateLabel`,
  `elapsed`, `ago`, `sessionTitle`, `envName`, `agentName`, `agentRole(type, t)`; plus
  `typeLabel(type)` (no `t`).
- `packages/web/test/i18n.test.ts`, `packages/web/test/format.test.ts`.

## Usage
- Add a key to `fr.ts` first, then to `de.ts` and `en.ts`.
- Texts with variables are functions in the dictionary; plurals go through `plural.ts`.
- Components call `useT()`. Non-React code receives `t: Messages` as a parameter; reuse or
  extend the `format.ts` helpers rather than formatting in components.
- `rooms` is `satisfies Record<RoomId, string>`: a new `RoomId` needs a name in all three
  languages.
- `posts` is `satisfies Record<PostId, { title, role, who }>` in `fr.ts`: a new `PostId`
  needs all three texts in all three languages. `who` is a translated sentence that names
  agent types. Related keys: `postList.title`, `postCard.who`, `postCard.close`.
- Subagent type names are displayed through `typeLabel` everywhere (3D tags, roster list,
  agent card, rest card): capital at the start and after `-` / `:` (`samuel-morse` →
  `Samuel-Morse`); `agentName` uses it for subagents. Ids, `LOOKS` / `STATIONS` keys and raw
  data stay raw; the Debug page shows raw types.
- `agentRoles`: one short role per `LOOKS` key (lower-case type), read by `agentRole` via
  `Object.hasOwn` on the lower-cased type, else `restCard.unknownRole`. `i18n.test.ts`
  enforces exact key parity with `LOOKS`: a new `LOOKS` type needs a role in all three
  languages. Related keys: `roster.title`, `restCard.{kind,close,unknownRole}` (card:
  `docs/ai/agent-lifecycle.md`).

## Notes
- The server never produces display text. A missing session title is sent as `title: null`
  (client shows `t.session.untitled` via `sessionTitle`); the virtual environment is sent
  with `virtual: true` and named client-side (`envName`); an API error without a message
  leaves `toolDetail` undefined (client shows `t.panel.apiError`).
- 3D text drawn on a canvas follows the same rule: the dungeon name sign
  (`docs/ai/night-forest.md`) gets its text from `envName(env, t)`, so a real env shows its
  name (user data, untranslated) and the virtual env its translated placeholder.
- Server logs and HTTP error bodies stay in French and are out of scope.
- Product name: "Agents’ lAIr" (typographic apostrophe U+2019; "lair" fits a dungeon, with
  "AI" capitalised), a proper noun identical and never translated in FR/DE/EN. Single
  source: `APP_NAME_PARTS = { before, bold, after }` in `i18n/index.ts`, from which
  `APP_NAME` (plain text) is derived. Reuse: styled/visible brand → `<AppName />`
  (`packages/web/src/ui/AppName.tsx`, used by the header brand in `App.tsx`; renders
  `<span lang="en">` with "AI" in `span.brand__ai`, bold is visual only, hence no
  `<strong>`); plain text (every `document.title`) → `APP_NAME`. Never hard-code or
  translate it. `.brand` in `styles.css` must stay without `text-transform`: the lAIr
  casing is the pun. `packages/web/index.html` (static title and meta description), the
  server console line in `packages/server/src/index.ts` and
  `scripts/{install,uninstall}-hooks.mjs` repeat it as literals because they cannot import
  `APP_NAME`; update them together on any rename.
- Terminology: UI text calls each Claude app environment a dungeon of the kingdom
  (donjon / Verlies / dungeon), never bureau / office nor entreprise / Unternehmen /
  company.
- Technical identifiers deliberately keep "agent-office" / "office": `@agent-office/*`
  packages, `AGENT_OFFICE_*` env vars, the `x-agent-office-token` header, the
  `~/.claude/agent-office` relay dir, the localStorage key `agent-office.lang`, launch.json
  names and code identifiers (`Office.tsx`, `useOffice`, the `office` key, `office__*`
  classes). Do not rename them: installed hooks depend on them.
- `i18n.test.ts` checks key parity, same function arity as French, no empty strings, room
  coverage, post coverage and `agentRoles` / `LOOKS` parity. `format.test.ts` checks formatting per language.
- vitest runs in node: web tests must not import `store.ts`, `useT.ts`, or any `.tsx` file.
