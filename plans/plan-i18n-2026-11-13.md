# Plan d'implémentation : interface trilingue FR / DE / EN

*Rédigé le 2026-11-13*

## Objectif

L'interface d'Agent Office s'affiche en français, en allemand ou en anglais. On change de langue à la volée, sans recharger la page, avec un bouton placé dans un coin de l'écran. Ensuite, tout nouveau texte affiché doit exister dans les trois langues : un oubli doit casser la compilation au lieu de passer inaperçu.

## Exigences

### Fonctionnelles
- Trois langues : `fr`, `de`, `en`.
- **Première visite** : la langue du navigateur (`navigator.languages`, premier élément dont le préfixe est `fr`, `de` ou `en`). Sinon, repli sur le français.
- **Choix mémorisé** dans `localStorage` (clé `agent-office.lang`). Une lecture ou écriture qui échoue (navigation privée, stockage bloqué) ne casse rien : on retombe sur la détection.
- **Sélecteur** dans le coin haut droit de la barre du haut, présent sur toutes les pages (accueil, environnement, debug) : trois boutons `FR | DE | EN`, l'actif marqué `aria-pressed="true"`. Chaque bouton porte son propre `lang` et un nom accessible dans sa langue (« Français », « Deutsch », « English »).
- Le changement met à jour immédiatement tous les textes, y compris :
  - `<html lang>` et `document.title` ;
  - les panneaux (détail d'agent, liste des sessions, historique, légende, sélecteur d'entreprise) ;
  - les étiquettes 3D des salles (`Html` de drei) ;
  - les libellés ARIA et les annonces du `StatusAnnouncer` ;
  - les durées (« 3 min », « il y a 2 h ») et les heures de la page Debug, formatées selon la langue.
- Les noms de salles sont traduits (ex. Bibliothèque / Bibliothek / Library).
- Les textes de repli aujourd'hui fabriqués par le serveur en français deviennent des indicateurs, traduits côté client :

  | Aujourd'hui (serveur) | Demain |
  |---|---|
  | `title: 'Session sans titre'` (`inventory.ts`) et `'Session terminal'` (`reducer.ts`, quand le dossier n'a pas de nom) | `title: null` → le client affiche « Session sans titre / Unbenannte Sitzung / Untitled session » |
  | environnement `'Hors environnement'` (`reducer.ts`) | le nom reste, mais le client affiche la traduction quand `virtual: true` |
  | `toolDetail: 'Erreur API'` quand l'erreur n'a pas de texte | `toolDetail` absent → le client affiche « Erreur API / API-Fehler / API error » |
  | `agentType: 'Session principale'` de l'agent principal | inchangé : jamais affiché (le nom d'un agent principal est le titre de sa session) |

### Non fonctionnelles
- **Complétude garantie par le typage** : le dictionnaire français définit la forme ; l'allemand et l'anglais sont typés `Messages` (même forme, toutes les clés obligatoires). Une clé absente ou en trop dans une langue fait échouer `npm run typecheck`.
- **Aucune nouvelle dépendance** : module maison et API `Intl` du navigateur (`Intl.PluralRules`, `Intl.RelativeTimeFormat`, `Intl.DateTimeFormat`).
- **Accessibilité** : le sélecteur est utilisable au clavier, son état est annoncé, `lang` est juste sur la page et sur chaque bouton (WCAG 3.1.1 et 3.1.2).
- **Performance** : les trois dictionnaires (~90 textes chacun) sont dans le bundle ; pas de chargement à la demande, inutile à cette taille.

### Hors périmètre
- Les messages du serveur qui ne s'affichent pas dans l'interface : logs console (`index.ts`), corps d'erreur HTTP 403 (`app.ts`), scripts `hooks:install`.
- Les données elles-mêmes : titres de sessions, noms d'environnements, descriptions de tâches, derniers messages des agents. Elles restent dans la langue où elles ont été écrites.
- La documentation (`docs/`, `README.md`) reste en français.
- Le `<meta name="description">` d'`index.html` reste en français (page `noindex`, servie avant le JavaScript).

## Approche technique

### Branche et worktree
- `main` = `97d5e70`, identique à `feat/carte-donjon` côté commits. Le dépôt n'a pas de remote : pas de `git pull` possible, on part de `main` local.
- Création d'un worktree à côté du dépôt, `F:\claudeworkshop-i18n`, sur une nouvelle branche `feat/i18n` issue de `main`. Les 11 fichiers modifiés du donjon restent intacts dans `F:\claudeworkshop`.
- `npm install` dans le worktree (les `node_modules` ne sont pas partagés).

### Architecture
- `packages/web/src/i18n/`
  - `fr.ts` : dictionnaire de référence, exporte `fr` et le type `Messages = typeof fr` (en élargissant les littéraux en `string`).
  - `de.ts`, `en.ts` : `export const de: Messages = { … }`.
  - `index.ts` :
    - `type Lang = 'fr' | 'de' | 'en'`, `LANGS`, `detectLang()`, `loadLang()` / `saveLang()` protégés par `try/catch` ;
    - le dictionnaire actif et la langue vivent dans le store zustand existant (`lang`, `setLang`), ce qui suffit à re-rendre tout ce qui lit `useOffice((s) => s.lang)` ;
    - hook `useT()` qui renvoie `{ t, lang }` ; `t` est le dictionnaire de la langue courante, accédé par propriété (`t.panel.close`), donc auto-complété et vérifié par TypeScript ;
    - les textes avec variables sont des fonctions dans le dictionnaire (`activeSessions: (n: number) => …`), le pluriel passe par `Intl.PluralRules(lang)`.
  - `setLang` met aussi à jour `document.documentElement.lang`.
- `format.ts` : `stateLabel`, `elapsed`, `ago`, `agentName` prennent la langue (ou le dictionnaire) en paramètre au lieu de renvoyer du français. `ago` utilise `Intl.RelativeTimeFormat`. `elapsed` garde sa forme compacte (« 3 h 05 ») avec des unités issues du dictionnaire.
- Noms de salles : `t.rooms` est typé `Record<RoomId, string>`. La constante `ROOM_NAMES` de `format.ts` disparaît au profit de `t.rooms[id]`.
- `StatusAnnouncer` : les phrases sont construites avec le dictionnaire de la langue courante au moment de l'annonce. Un changement de langue n'annonce rien (il ne modifie pas les états).
- Page Debug : `toLocaleTimeString(lang)` au lieu de `'fr-FR'`.
- `document.title` : `App.tsx` lit `t` et la langue, les effets en dépendent.

6. `packages/web/src/ui/AgentPanel.tsx`, `SessionList.tsx`, `History.tsx`, `EnvSwitcher.tsx`, `StatusAnnouncer.tsx`, `Debug.tsx` : textes via `t`.

## Fusion avec la branche du donjon

`feat/carte-donjon` remplace les 4 salles par 15 et déplace les noms de salles dans `layout.ts` (`ROOMS[].name`, `ROOM_NAMES`). Les deux branches touchent `format.ts`, `AgentPanel.tsx`, `Room.tsx` et `shared/src/index.ts` : la seconde fusionnée aura des conflits.

Le typage les rend sûrs : une fois les 15 `RoomId` du donjon fusionnés, `t.rooms` (`Record<RoomId, string>`) ne compile plus tant que les 15 noms ne sont pas traduits dans les trois langues. Résolution prévue : retirer `name` de `ROOMS` dans `layout.ts` et lire `t.rooms[id]`. Les noms des 15 salles en allemand et en anglais seront à rédiger à ce moment-là (ou tout de suite dans ce plan si vous préférez, voir la question en fin de plan).

## Cas limites

- `navigator.languages` vide ou absent (certains navigateurs embarqués) : repli sur `navigator.language`, puis sur `fr`.
- Valeur inconnue dans `localStorage` (ancienne version, édition à la main) : ignorée.
- Langue changée pendant qu'une annonce du `StatusAnnouncer` est en attente (50 ms) : elle part dans la langue où elle a été construite. Acceptable.
- Étiquette 3D d'une salle montée avant le canvas (problème déjà contourné dans `Room.tsx`) : vérifier qu'elle se met à jour au changement de langue.
- Allemand plus long que le français : vérifier dans le navigateur que la légende, le sélecteur d'entreprise et les cartes d'environnement ne débordent pas.

## Vérification
- `npm run typecheck` et `npm test` dans le worktree.
- Aperçu dans le navigateur intégré : bascule FR → DE → EN sur l'accueil et sur un environnement, rechargement de la page (langue conservée), vérification de `<html lang>`, du titre de l'onglet et des étiquettes 3D.
- Portes qualité prévues : `dexter`, `hermione`, `gatsby` et `timmy` (interface rendue modifiée), `neo` (stockage navigateur, contrat serveur/client modifié), `curator` (règle durable), `otis` si le README décrit l'interface.
